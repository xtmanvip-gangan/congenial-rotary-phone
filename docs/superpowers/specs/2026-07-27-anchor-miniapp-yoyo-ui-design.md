# 主播端小程序 YOYO UI 设计规格

日期：2026-07-27  
适用项目：`miniapp-anchor`  
设计交付：覆盖全部业务页面与关键状态的可编辑 Figma 文件

## 1. 设计目标

为主播角色的小程序建立一套年轻、时尚、有 IP 识别度，同时能够承载复杂业务信息的完整 UI。

设计需要同时满足：

- 保留参考产品 Lovekey 的年轻感、粗体排版、圆角卡片和 IP 融合方式。
- 使用黑白作为主要信息骨架，避免页面因彩色过多而失去层级。
- 使用 YOYO 蓝作为品牌主色，腮红粉作为情绪与奖励点缀。
- 使用低饱和蓝粉柔光背景营造轻盈氛围。
- 让 YOYO 参与引导、提醒、空状态和完成反馈，而不是仅作为装饰贴图。
- 覆盖代码中现有的 10 个路由页面以及加载、失败、空状态、待确认、驳回等重要状态。

## 2. 视觉方向

### 2.1 核心色

| 角色 | 色值 | 使用场景 |
| --- | --- | --- |
| 曜石黑 | `#151515` | 标题、正文、高对比按钮、选中标签 |
| 纯白 | `#FFFFFF` | 页面主体、内容卡片、表单容器 |
| YOYO 蓝 | `#6FA8FF` | 主按钮、关键数据、选中态、品牌识别 |
| 腮红粉 | `#FFD6E0` | 奖励、完成反馈、温柔提醒、少量星星 |
| 中性浅灰 | `#F5F5F5` | 输入区、分组背景、禁用态 |

中性浅灰不作为品牌色，只用于建立界面层级。

### 2.2 柔光背景

页面以白色为基础，上方叠加低透明度的蓝粉径向柔光：

- 左上：YOYO 蓝，透明度 12%–20%。
- 右上：腮红粉，透明度 14%–22%。
- 蓝粉交叠可自然形成淡紫，不单独引入紫色。
- 柔光在页面上部 40%–50% 内逐渐淡出。
- 内容密集区域恢复白色，确保表单和列表清晰。

完整柔光背景用于：

- 登录欢迎页
- 主播入驻与资料完善
- 等待运营确认
- 空状态与完成反馈
- 个人中心

活动、培训、记录、提报等高信息密度页面仅在页头使用柔光，内容区保持白色或中性浅灰。

### 2.3 字体与层级

- 中文字体：`PingFang SC`，Figma 中使用可用的苹方对应字体。
- 大标题：28–32 px，Bold/Heavy，紧凑行高。
- 页面标题：24–28 px，Bold。
- 卡片标题：16–18 px，Semibold/Bold。
- 正文：14–16 px，Regular/Medium。
- 辅助信息：12–13 px，Regular/Medium。
- 关键数字允许使用更粗字重和更紧字距。

整体排版以粗黑标题配合大留白，延续参考页面的年轻感。

### 2.4 卡片与组件

- 页面圆角：大卡 24 px，普通卡 16–18 px，标签为胶囊形。
- 卡片以白底为主，使用轻阴影或浅灰分组，不使用粗边框。
- 主要按钮使用 YOYO 蓝；高对比特殊操作可使用黑底白字。
- 腮红粉不作为常规主按钮背景。
- 状态色优先通过文字、图标和浅色标签表达，不引入额外高饱和品牌色。
- 底部导航保持白色悬浮卡片感，当前项使用黑色或 YOYO 蓝强化。

## 3. YOYO IP 使用规范

### 3.1 角色分工

- 大形象：登录页、首页问候、空状态、完成反馈、等待确认。
- 半身形象：页头提醒卡、今日待办、个人中心助手。
- 小头像：课程推荐、运营提示、帮助入口。
- 不在每张普通业务卡中重复放置 YOYO，避免视觉疲劳。

### 3.2 星星母题

- 星星是统一装饰元素，不是随机撒点。
- 每张卡片最多在四角放置 1–2 颗星星。
- 蓝色星星用于品牌、信息与成长。
- 腮红粉星星用于奖励、完成与温柔提醒。
- 重要成长进度可使用星轨或“点亮星星”的叙事。
- 普通列表只保留极小的角标星星。
- 星星不得覆盖文本、状态标签或点击区域。

### 3.3 背景线稿

柔光背景可加入低透明度、大尺寸、裁出屏幕边缘的线稿：

- YOYO 星星轮廓
- 兔耳轮廓
- YOYO 半张脸轮廓
- 弯曲星轨

线稿以白色或 YOYO 蓝低透明度呈现，不与正文争夺注意力。

## 4. 信息架构

底部导航维持四个一级入口：

1. 活动
2. 培训
3. 记录
4. 我的

登录、资料完善、岗前确认、活动记录、提报和记录详情为流程型二级页面。

## 5. 页面设计范围

### 5.1 欢迎与登录 `pages/index/index`

设计内容：

- YOYO 大形象与品牌标识。
- 蓝粉柔光背景与大尺寸星星/兔耳线稿。
- 企业微信登录主按钮。
- 登录说明与隐私提示。

状态：

- 检查登录态
- 欢迎登录
- 登录中
- 路由中
- 登录失败
- 非企业微信环境提示

### 5.2 资料完善与等待确认 `pages/activate/index`

设计内容：

- 入驻步骤提示。
- 头像上传与企微头像同步。
- 昵称、UID、手机号、运营老师。
- 新主播/老主播身份标签。
- 提交资料主操作。

状态：

- 加载
- 加载失败
- 新主播资料填写
- 老主播选择运营
- 运营列表为空
- 手机号输入错误
- 上传头像中
- 提交中
- 等待运营确认

### 5.3 活动首页 `pages/activities/index`

设计内容：

- 问候与今日重点。
- YOYO 半身提醒卡。
- 进行中、未开始、已结束、全部筛选。
- 活动封面、玩法、时间、倒计时与提报入口。
- 我的活动记录入口。

状态：

- 默认进行中活动
- 待运营确认，不可提报
- 未开始活动
- 已结束活动
- 空列表
- 加载
- 登录失败
- 数据加载失败

### 5.4 单活动记录 `pages/activity-records/index`

设计内容：

- 活动封面页头。
- 审核状态、发放状态、归属确认状态。
- 直播时间、运营老师、奖励结果、驳回原因。
- 查看详情与修改记录。

状态：

- 有记录
- 无记录
- 参数缺失
- 加载失败
- 不可修改

### 5.5 活动提报与修改 `pages/submit/index`

设计内容：

- 分步式填写：直播信息、活动数据、截图凭证。
- 礼物收集与 PK 值两种表单。
- 奖励档位与实时奖励预览。
- 最多 9 张截图上传、预览与删除。
- 新建和修改模式。

状态：

- 礼物活动
- PK 活动
- 奖励预览中
- 命中奖励
- 未命中奖励
- 上传中
- 表单校验错误
- 提交中
- 已审核/已发放不可修改
- 运营归属未确认
- 加载失败

### 5.6 全部记录 `pages/records/index`

设计内容：

- 个人提报总览。
- 审核中、已通过、已驳回等筛选。
- 奖励发放状态。
- 活动类型、直播时间和奖励摘要。

状态：

- 多状态记录列表
- 空记录
- 加载
- 登录失败
- 加载失败

### 5.7 记录详情 `pages/record-detail/index`

设计内容：

- 活动信息与状态摘要。
- 直播时间、运营老师、提交内容。
- 礼物明细或 PK 值。
- 奖励结果。
- 截图凭证画廊。
- 驳回原因和修改入口。

状态：

- 审核中
- 已通过
- 已驳回
- 已发放
- 可修改
- 不可修改
- 加载失败

### 5.8 培训中心 `pages/training/index`

设计内容：

- 开放课表、我的进度、推荐课程三个视图。
- 星图式成长进度。
- 课程序号、老师、时间、剩余名额、候补人数。
- 报名、候补、取消报名和复制入会链接。
- 学习类型：首学、复习、补学。

状态：

- 可报名
- 已报名
- 候补
- 已学
- 待补学
- 补学排队
- 已补学
- 无开放课表
- 无推荐课程
- 加载失败

### 5.9 岗前确认 `pages/onboarding/index`

设计内容：

- 7 个岗前节点的进度星轨。
- 待确认事项卡片。
- 运营提交的证据信息。
- 培训确认清单。
- 确认通过与驳回原因输入。

状态：

- 有待确认节点
- 无待确认节点
- 全部节点进度
- 确认抽屉
- 驳回输入
- 提交中
- 加载失败

### 5.10 我的 `pages/mine/index`

设计内容：

- 主播档案、所属运营、经营状态。
- YOYO 待办助手。
- 岗前确认、培训、活动与记录待办。
- 常用入口。
- 退出登录。

状态：

- 真实登录
- 预览模式
- 资料缺失
- 有待办
- 无待办
- 登录态丢失
- 档案加载失败

## 8. 验收标准

- 10 个路由页面均有主场景设计。
- 关键业务状态均有独立画面或组件变体。
- 所有界面使用统一的色彩、字体、间距、圆角与星星规则。
- YOYO 的使用具有业务意义，不出现无目的重复。
- 蓝粉柔光不会影响正文对比度。
- 表单、列表和状态信息在移动端清晰可读。
- Figma 中页面、组件和图层命名清晰，可供开发实现。
- 逐页截图检查，无文字裁切、重叠、错位或底部安全区问题。
