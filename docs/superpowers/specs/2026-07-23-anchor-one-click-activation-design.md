# 主播档案一键开通与企微提醒设计

## 目标

把主播档案开通改为“审核老师预先确认资料，主播本人一键开通”：

- 审核老师负责填写主播昵称、企微 UID、固定运营和入会时间。
- 主播通过企微身份登录小程序，只核对资料并点击开通。
- 运营老师继续承担归属确认，确认后启动岗前孵化进度。
- 审核老师手动触发企微提醒，发送链路复用礼物提报现有通知能力。

## 角色职责

### 审核老师

1. 确认主播已经入会。
2. 创建档案开通任务。
3. 填写主播昵称、企微 UID、分配的运营老师和入会时间。
4. 在主播开通前修改任务资料。
5. 确认资料无误后手动发送企微提醒。
6. 查看提醒发送结果，必要时重新发送。

### 主播

1. 使用企业微信身份登录主播小程序。
2. 查看系统匹配出的主播昵称、所属运营和入会时间。
3. 信息正确时点击“确认并开通档案”。
4. 信息错误时联系审核老师，不在小程序自行修改。

### 运营老师

1. 在 Web 端接收待确认的主播归属。
2. 确认后建立固定运营关系。
3. 按八个岗前孵化节点推进主播。

## 数据模型

`anchor_activation_tasks` 调整为：

- 保留 `expected_wecom_user_id`，用于和主播小程序登录身份精确匹配。
- 保留 `wecom_display_name_snapshot`，其业务含义统一为“企微昵称＝抖音直播昵称＝主播昵称”。
- 保留 `membership_completed_at`。
- 删除 `device_ready_at`。
- 新增 `operator_id`，关联审核老师已经分配的固定运营。
- 保留审核老师、任务状态、提醒时间、提醒次数和已激活档案关联。

数据库迁移必须保留已有任务。已有记录的运营归属按以下顺序回填：

1. 已激活任务使用关联主播档案的当前运营。
2. 未激活任务无法可靠推断运营时保持为空，并在审核端标记为“待补充运营”；补充后才允许发送提醒和开通。

新增任务必须填写运营老师，接口不接受空运营。

## 审核端 Web

### 创建任务

表单字段：

- 主播昵称
- 企微 UID
- 分配运营
- 入会时间

不再展示或提交设备调试时间。

创建成功后任务状态为“待发送”，不会自动发送企微提醒。

### 修改任务

主播尚未开通时，审核老师可以修改全部四项资料。任务已经开通后禁止通过开通任务修改资料。

如果主播已经开通、但运营驳回归属，审核端提供“重新分配运营”操作。审核老师选择新的运营后，系统更新主播档案的当前运营并创建新的待确认归属记录；已经建立的主播档案不删除，也不要求主播再次开通。

任务列表显示：

- 主播昵称
- 企微 UID
- 所属运营
- 入会时间
- 开通状态
- 最近提醒时间
- 提醒次数

操作：

- 编辑资料
- 发送提醒／重新发送提醒
- 取消任务

### 提醒反馈

- 发送成功：显示“提醒已发送”，更新最近提醒时间和次数。
- 发送失败：显示企微接口返回的具体原因，任务不伪装成已成功发送。
- 失败后允许重新发送。

## 企微提醒

复用 `NotificationsService` 和 `WecomService.sendAgentTextMessage`，与礼物提报通知使用相同的企微自建应用配置、发送日志、失败记录和异常监控。

消息格式：

```text
【悦总统】主播档案开通提醒
主播：{主播昵称}
所属运营：{运营老师}
入会时间：{入会时间}
请打开主播小程序，核对资料后完成档案开通。
```

每次由审核老师主动点击发送。首次发送和重新发送都创建可追踪的通知记录；任务的提醒次数只在真实发送成功后增加。

## 主播小程序

### 未具备开通条件

如果登录企微 UID 没有可用任务，显示“尚未收到档案开通任务，请联系审核老师”。

### 待开通

显示只读确认卡：

- 主播昵称
- 所属运营
- 入会时间

不显示企微 UID，不提供任何输入框或运营选择器。

按钮文案为“确认并开通档案”。

### 一键开通

主播点击按钮后，接口只依据当前登录企微身份定位任务，不接收主播昵称或运营 ID：

1. 校验任务为待开通或已发送状态。
2. 校验任务已经配置有效运营。
3. 使用任务昵称创建主播档案。
4. 使用任务运营创建“待运营确认”的归属记录。
5. 将开通任务更新为“已开通”并关联主播档案。

重复点击必须幂等：已有档案时返回现有档案，不重复创建。

### 开通后

- 待运营确认：显示已分配运营和等待确认提示。
- 运营驳回：主播不能自行选择其他运营，显示“归属未确认，请联系审核老师重新分配”。审核老师在 Web 端重新分配后，主播只需刷新确认状态。
- 运营确认：进入主播中心。

## 运营确认与岗前流程

运营确认逻辑继续保留。确认后：

1. 归属状态改为已确认。
2. 固定运营写入主播档案。
3. 初始化八个岗前孵化节点。
4. 第一个“运营已接收”节点自动完成。

八个节点：

1. 运营已接收
2. 主页整理
3. 直播软件设置
4. 辅助软件安装
5. 岗前学习
6. 开播前确认
7. 完成首播
8. 完成首播复盘

## 权限与一致性

- 只有审核老师、培训管理员和密码超级管理员可以创建、编辑、发送或取消开通任务。
- 审核老师默认只能管理自己创建的任务；培训管理员和超级管理员可以管理全部任务。
- 主播只能读取并开通与本人企微 UID 匹配的任务。
- 所选运营必须是启用状态且拥有运营角色。
- 已开通任务禁止编辑和取消。

## 错误处理

- 企微 UID 已有有效任务：阻止重复创建并提示现有状态。
- 运营已停用或失去运营角色：阻止发送和开通，要求审核老师重新分配。
- 企微提醒失败：保留失败日志和原因，不增加成功提醒次数。
- 主播身份不匹配：不泄露其他主播资料，只提示没有可用任务。
- 数据库迁移后的旧任务缺少运营：审核端提示补充，主播端不可开通。

## 测试与验收

### API

- 创建任务只接受昵称、企微 UID、运营和入会时间。
- 审核老师可在开通前修改任务。
- 已开通任务不可修改。
- 手动发送调用企微通知服务。
- 只有发送成功才更新提醒次数和时间。
- 主播一键开通不接受昵称或运营参数。
- 开通结果使用任务中的昵称和运营。
- 重复开通保持幂等。
- 运营确认后初始化岗前进度。

### Web

- 创建表单不再出现设备调试时间。
- 创建和编辑必须选择运营。
- 提醒成功和失败都有明确反馈。

### 小程序

- 待开通页只显示只读资料和一个开通按钮。
- 无任务、待确认、归属驳回和已启用状态展示正确。
- 生产构建成功，可导入微信开发者工具。

### 线上验收

- 使用审核角色创建和编辑测试任务。
- 手动发送后主播收到企微应用消息。
- 主播通过开发版小程序一键开通。
- 运营确认后可以看到主播及八个岗前节点。

## 部署与交付

- 数据库迁移先备份并在副本演练。
- 部署 API 和 Web 到 `https://ac.ydwy.net` 测试环境。
- 重新构建主播微信小程序。
- 交付目录为 `miniapp-anchor/dist`，用户使用微信开发者工具导入、预览和真机测试。
- 不自动提交微信审核或发布正式小程序。
