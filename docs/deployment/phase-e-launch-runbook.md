# 阶段 E 上线与回退手册

## 1. 上线原则

- 首次上线先选择少量内部主播和老师试运行。
- 本地和 CI 不连接生产数据库，不发送真实企微消息，也不创建真实腾讯会议。
- 生产密钥只通过服务器环境变量或密钥服务注入，不能写入仓库、日志或截图。
- 测试数据清理与应用部署分开执行；部署脚本不会自动删除业务数据。

## 2. 上线前准备

1. 确认超管只能从外部浏览器使用账号密码登录；其他员工只能从企微自建应用登录。
2. 设置 `NODE_ENV=production`、`DATABASE_URL`、`SESSION_SECRET`、企微、腾讯会议和 `CORS_ALLOWED_ORIGINS`。
3. 执行 `bash scripts/preflight.sh`。脚本只检查变量是否存在，不输出变量值。
4. 使用独立备份目录执行：

   ```bash
   SHOUJI_DATABASE_URL='由密钥服务注入' \
   SHOUJI_BACKUP_DIR='/明确的受保护备份目录' \
   bash scripts/backup-postgres.sh
   ```

5. 保存备份文件路径、大小和受控存储位置，由另一名管理员确认备份可读。
6. 调用超管清理预览接口，核对主播、提报、审核、奖励和通知数量。员工账号、活动、礼物项和奖励规则必须不受影响。

## 3. 构建与迁移

1. 执行 `npm --prefix api run prisma:generate` 和 `cd api && npx prisma validate`。
2. 执行 API 全量测试、类型检查、构建与生产依赖审计。
3. 执行 Web 构建和主播小程序构建。
4. 在维护窗口按迁移编号依次应用 SQL；记录执行人和时间。
5. 启动 API 后检查 `/api/health`，再启动 Web。

## 4. 冒烟检查

- 外部浏览器超管密码登录成功，企微入口不能把超管识别为员工。
- 主播小程序本人登录后能激活档案并选择运营。
- 运营只能看到自己的主播，能更新岗前、首播和首播复盘。
- 礼物提报自动带出固定运营，历史记录保留运营快照。
- 培训场次能发布、报名、候补、取消和补位。
- 在测试场次验证腾讯会议创建、企微通知、参会同步和人工匹配。
- 运维中心能看到任务运行和脱敏后的接口异常。

## 5. 定时任务

生产调度器只调用已定义的受保护任务接口，不允许传入任意任务名：

- 每 5 分钟执行开课前一小时提醒。
- 每 10 分钟执行失败通知重试。
- 每次运行都在 `system_job_runs` 留下幂等键、计数、状态和耗时。
- 连续出现 `failed` 或 `partial` 时，由培训管理员在运维中心处理。

## 6. 回退条件

出现登录角色串号、运营越权、固定运营归属错误、重复场次/报名/通知或迁移失败时，停止放量并回退应用镜像。若新版本已经写入新表，优先保留新表并回退应用；只有迁移破坏旧版运行时才执行数据库恢复。

## 7. 数据库恢复演练

先在隔离演练库验证，禁止把生产连接串当演练目标：

```bash
SHOUJI_DATABASE_URL='隔离演练库连接串' \
SHOUJI_RESTORE_FILE='/明确的备份文件绝对路径' \
CONFIRM_RESTORE='RESTORE_SHOUJI_DATABASE' \
bash scripts/restore-postgres.sh
```

恢复后核对健康检查、超管登录、主播档案、礼物提报、培训场次和任务运行记录。演练记录包含备份时间、恢复耗时、核对结果和责任人。
